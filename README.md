## Тестовое задание на позицию Fullstack разработчика (Python + React)

**Вводные:**
1. Здесь представлен MVP проект файлообменника. Он позволяет загружать файлы, проверяет их на подозрительный контент и отправляет алерты;
2. Репозиторий содержит в себе бэкенд и фронтенд части;
3. В обоих частях присутствуют баги, неоптимизированный код, неудачные архитектурные решения.

**Задачи:**
1. Проведите рефакторинг бэкенда, не ломая бизнес-логики: предложите свое видение архитектуры и реализуйте его;
2. (Дополнительно) На бэкенде есть возможность неочевидной оптимизации - выполните ее;
3. (Дополнительно) Разбейте логику фронтенда на слои;

**Запуск:**
1. ```docker compose -f docker-compose.dev.yml up --build```
2. ```docker exec -it backend alembic upgrade head```


**Открыть фронт:** ```http://127.0.0.1:3000/test``` 

**Открыть бэк:** ```http://127.0.0.1:8000/docs```

## Что сделано

1. Починил compose.
2. Подключение к базе вынес в один файл. Раньше API и воркер создавали его каждый у себя. Миграции берут адрес базы из этого же файла.
3. Загрузка пишет файл на диск чанками, пустой файл по-прежнему отвечает 400 и не остаётся в storage. Скачивание берёт путь из `get_file_path`. `create_alert` убран, так как функция нигде не вызывается, сам алерт по-прежнему создаёт воркер в `tasks.py`.
4. Объединил три задачи воркера в одну `scan_file_for_threats`. Держать их раздельно нет смысла, так как шаги и так идут строго друг за другом, а три задачи давали три сообщения в Redis и три раза будили воркера. Правила проверки и тексты алертов те же.
5. Удаление файла больше не упирается в алерты - у внешнего ключа `alerts.file_id` теперь стоит `ON DELETE CASCADE`, и Postgres убирает алерты сам. Раньше после проверки DELETE падал, потому что на строку файла ссылались алерты, а ключ был без cascade.
6. Вынес из `page.tsx` запросы и типы в отдельные файлы. Адрес бэкенда поменял на `http://127.0.0.1:8000`, на Windows localhost может уходить в IPv6 и тогда запрос зависнет.
